# 架构与协议

## 总体结构

```
┌─────────────── 公网服务器 ───────────────┐          ┌────────── 内网机器 ──────────┐
│                                          │          │                              │
│  Web面板 ── Panel HTTP API ──┐            │   隧道    │  client 进程                 │
│  (随机路径+白名单+免密/密码)  │            │ ◄─────── │  ├ 连接/重连(指数退避)        │
│                              ▼            │  TCP+smux │ ├ 控制流: 收规则/报状态      │
│  server 进程                 │            │          │  ├ 穿透: 收流→拨内网目标      │
│  ├ 隧道端点(鉴权/会话管理)   │            │          │  ├ 反向: 本地监听→开流回源    │
│  ├ 正向/穿透监听器(TCP+UDP)  │            │          │  └ UDP: connID↔socket 映射   │
│  ├ 反向回源(TCP拨号/UDP帧)   │            │          │                              │
│  └ 规则热更新/统计/日志环形  │            │          │  (无状态: 目标由流头下发)     │
└──────────────────────────────────────────┘          └──────────────────────────────┘
```

- 单二进制三种角色：`server` / `client` / `service`（Windows SCM 包装）
- 客户端**无状态**：不存规则，穿透数据流的每个流头都带目标地址；反向规则经控制流全量下发
- 配置集中在服务器，JSON 原子写（tmp + rename），修改即热生效

## 隧道协议

传输层：一条客户端主动发起的 TCP 连接，默认包裹 **TLS**（server 端自签证书或有证书，client 可用 SHA-256 指纹锁定服务器身份），鉴权后升级为 [smux](https://github.com/xtaci/smux) 多路复用会话。全部转发数据与协议帧都在 TLS 内传输；两端 `no_tls: true` 时退化为明文。

### 1. 鉴权（smux 之前，TLS 内的 JSON 帧）

```
client → server: [2B 大端长度][JSON AuthRequest{token, host}]
server → client: [2B 大端长度][JSON AuthReply{ok, message}]
```

token 与服务器 `clients[].token` 常数时间比对；同一客户端重连会踢掉旧会话。

### 2. 流的类型

每个 smux 流首帧是 `[2B 长度][JSON StreamHeader{ID, Target, UDP}]`：

| 流 | 发起方 | 用途 | 后续载荷 |
|---|---|---|---|
| 控制流（`ID="__control__"`） | server | 下发反向规则 `RulePush`；接收状态 `ReverseStatus` | JSON 帧 |
| 穿透数据流 | server（每条 visitor 连接一条） | `Target`=客户端内网目标 | 裸 TCP 字节 |
| 反向数据流 | client（每条 visitor 连接一条） | `Target`=服务器侧目标 | 裸 TCP 字节 |
| UDP 帧流（`UDP=true`） | server(穿透) / client(反向)，每规则一条 | | UDP 帧 |

`ID` 为规则 ID，用于按规则归集流量统计。

### 3. UDP 封帧

一条规则的所有 UDP 会话复用一条流，按 `connID` 区分访客：

```
[4B connID][2B 长度][payload]
```

- 发起侧：visitor 地址 → connID 映射；收到回包按 connID 还原目的地址
- 回源侧：connID → 到目标的 UDP socket（空闲 90 秒回收）

### 4. 控制流消息

```
server → client: RulePush{rules: [ReverseRule{ID,Name,Proto,Listen,Target}]}   // 全量，变更即推
client → server: ReverseStatus{ID, OK, Err}                                    // 监听启停结果
```

客户端按 RulePush diff 本地监听器：新增启动、变更重启、消失停止；会话断开全部清理，重连后服务器重推。

## 流量统计

服务器侧每规则一组原子计数器：`BytesIn/BytesOut`（visitor↔target 双向字节）、`Conns`（当前并发）、`ConnsTotal`。
面板前端每 2 秒轮询 `/api/rules`，用相邻两次采样差值算速率，不做历史存储。

## 白名单判定

```
放行 = 本机回环
     ∪ 本机任意网卡地址（保证反向隧道访问面板可用）
     ∪ ip_whitelist 手动配置（IP 或 CIDR）
     ∪ 在线客户端的隧道来源 IP（自动）
```

## 已知取舍

- 隧道不加密（token 仅鉴权）；需要加密自行外层套 TLS
- UDP visitor 表不设过期，规模上限 ≈ 独立访客地址数
- 反向规则在客户端的监听状态依赖控制流回传，面板对该类规则的 Running 以回传结果为准
- 外部依赖仅 `xtaci/smux` 与 `golang.org/x/sys`
